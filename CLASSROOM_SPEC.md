R2 Class room core. Session lifecycle SCHEDULED -> LOBBY (opens 10 min before) -> LIVE (teacher starts) -> ENDED. In the lobby pupils run the pre-call check and see "waiting for teacher". Tokens come only from the backend, only for the teacher and enrolled pupils (short lifetime, re-issue allowed while the session is open); display name = first name only; no phone, email or card data in token metadata. Pupils join as viewers with canPublish=false, canPublishData=false, canUpdateOwnMetadata=false, enforced by the token AND by server-side permission updates, never by client checks. Stage modes per session, switchable live by the teacher: LISTEN_ONLY (nobody speaks), HAND_RAISE (default: a pupil raises his hand, the teacher grants voice or voice+camera), OPEN_STAGE (a pupil may take a free stage slot without approval). Granting uses the server API to give that one participant publish permission for the microphone, or microphone+camera; the pupil then switches camera/mic on and off himself while the grant lasts; the teacher can revoke at once; stage pupils start muted. At most CLASS_MAX_STAGE_PUPILS on stage, enforced atomically (transaction or lock) with a parallel-request test (the 11th is refused). Hand-raise is a rate-limited backend endpoint that persists state and sets a participant attribute so the teacher's roster updates live; a reconnecting client re-reads state from the backend. Teacher controls: mute all, mute/stop one pupil, spotlight a pupil (pupils get him as a tile), remove a pupil (server removes him and bans re-entry for this session), lock the room (no new tokens), end the class (server closes the room, attendance finalized). Teacher roster for 30 pupils: virtualized list, hand-raised first, connection-quality dot, stage state, actions. A teacher disconnect under 5 minutes keeps the room open and shows pupils "teacher is reconnecting"; absence beyond a configurable limit marks the session teacher_no_show. R3 Questions and chat in class. Two channels: class chat and a question queue. Pupils can ask in writing at any moment without camera or mic. A question: text up to 500 chars, optional "hide my name from classmates" (the teacher still sees it), one upvote per pupil. Teacher view sorted by pinned, upvotes, time; actions: call on the pupil (grants voice via R2), reply in text (visible to all), mark answered, answer later, pin, hide. Unanswered questions go to the recap (R8). Teacher restrictions, live and as class defaults: chatMode OPEN | QUESTIONS_ONLY | OFF, questionsMode OPEN | OFF, hand-raise on/off, slow mode (seconds between messages), mute one pupil for N minutes (chat and questions), delete a message. Limits: 1 chat message per 2 s and 3 questions per minute per pupil, max lengths; the contact-info detector for minors applies; report a message or pupil; every moderation action is logged. Delivery: reuse the existing realtime channel with message ids, resume from the last id after a reconnect, and a polling fallback every 2-3 s; messages persist and appear in the class feed. Pupils cannot upload files into class chat. Tests: a pupil calling teacher actions is denied, rate limits, restrictions enforced on the server, reconnect resume.

R4 Quality engine (web + mobile). Smooth on weak and changing networks: degrade, never freeze. The teacher publishes simulcast (about 3 layers, ~180p / 360p / 720p, 24-30 fps) with dynacast and adaptive stream on; speech microphone preset with echo cancellation, noise suppression, auto gain, DTX and RED where supported; check the codec options in the docs and prefer what hardware-decodes on cheap Android phones. Stage pupils publish small video (about 320x180 to 640x360, max 15-20 fps). Tile policy (config): pupil clients receive the teacher plus at most CLASS_VIEWER_TILES (default 3) video tiles (spotlighted or active speakers); everyone else is audio only; the teacher's grid shows only a paged set of visible tiles; never render more than 4 video views on mobile. Degradation ladder, automatic with a one-tap manual override and a visible banner: full video -> lower layer -> audio only -> "slides and board only" (PDF and board sync use the data path and page images, not video). Audio keeps priority over video at every step. Recovery steps back up only after the connection has been stable for a configurable time (no flapping). Reconnection: a "Reconnecting..." state; automatic rejoin with backoff and a fresh token after a drop or a Wi-Fi/mobile switch; after reconnect re-read backend state (permissions, hand/stage, presentation page, whiteboard snapshot, chat since last id, question queue); no duplicate attendance (extend the existing reconnect test, never weaken it). Keep the call alive in the background or with the screen locked (Android foreground service, iOS background audio); handle incoming phone calls and Bluetooth/speaker/earpiece. Pre-call check screen: permissions, device picker, mic level meter, a 5-second network check with a verdict (good / weak / audio only); teachers also get an upload check with a warning below a configurable minimum (placeholder 3 Mbps up) and advice to use a laptop on Wi-Fi or cable. All numbers in one commented config file; unit-test the config and the ladder as a pure state machine (inputs: bandwidth, loss, rtt, stability time).
