# DECISIONS

1. Existing app is a law-exam prep app (Expo + NestJS/Prisma/Postgres). The marketplace is added as a new `backend/src/marketplace/*` module tree and new tables; exam features untouched. Reason: brief says extend, do not rewrite.
2. Backend is its own nested git repo; milestone commits are made in `backend/` first, then the parent records the new commit. Reason: that is how the repo is laid out.
3. Root `.gitignore` was saved as UTF-16 (broken patterns, ignored `BRIEF.md`); rewrote it as UTF-8 with the same intent plus `.devdb/`. Reason: it silently ignored new root files.
4. Tests use Node's built-in test runner via ts-node (no jest). Reason: zero new downloads on an 8 GB laptop; integration tests hit a REAL throwaway local PostgreSQL (`scripts/dev-db.sh`); harness refuses any DB that is not localhost + name ending `_test`.
5. No linter exists in the project; "lint" = `tsc --noEmit` typecheck. Reason: adding eslint stack is a large download and a style change.
6. Role is a single enum field on User (STUDENT, GUARDIAN, TEACHER, ADMIN). Reason: simplest model fitting the brief; switching is one-way, adults with known birth date only. Marketplace admins reuse the existing separate `Admin` accounts and admin JWT (different secret) mapped to role ADMIN. Reason: do not invent a second admin system.
7. Guard re-reads user status/role from DB on every request instead of trusting JWT claims. Reason: suspended/deleted accounts must stop immediately.
8. Resources a user may not see return 404 (not 403) where existence would leak; permission failures return 403.
9. Date of birth can be set once through the API. Reason: editable DOB defeats the minor protections.
10. Migrations are generated only against the throwaway DB; nothing is ever applied to another database.
11. Teachers are listed/visible only when VERIFIED (strict). Reason: students include minors; trade-off is slower onboarding, the admin queue handles it. NEEDS LAWYER (what vetting is required for adults teaching minors).
12. Public identifier for a teacher is the TeacherProfile id, never the user id/email. Public view omits email, DOB, credential files.
13. Intro video is an external https link on an allowlist (YouTube/Vimeo), not an upload. Reason: avoids hosting/transcoding video and rendering user files on our origin; uploads via the S5 pipeline are possible later.
14. Credentials reference a StoredFile that must be owned by the teacher, purpose CREDENTIAL and status READY (set after S5 content check + scan hook).
15. Price is integer tiyin per 60 minutes (1 so'm = 100 tiyin), bounded by env-configurable min/max.
16. Double-booking is prevented by PostgreSQL exclusion constraints (teacher and student, REQUESTED/CONFIRMED) in addition to service checks; needs the `btree_gist` extension. Reason: only the database can close the race window. A race test proves exactly one of two simultaneous requests wins.
17. Minors cannot book for themselves; a linked (ACTIVE GuardianLink) guardian books for them. Adults book for themselves; guardians cannot book for adult pupils. Unknown date of birth => cannot book. NEEDS LAWYER (consent age, parental consent).
18. Reschedule = proposal that the OTHER side must accept (in-place move, same booking id). Not allowed inside the free-cancel window. Reason: avoids silent changes and keeps ledger/chat tied to one booking.
19. Join window: opens 5 min before start, closes 5 min after the scheduled end (env-configurable); no-show can be reported only after a 10 min grace. Late-cancel refund % defaults to 0 (NEEDS LAWYER/product decision), teacher cancel = 100% refund.
20. Teachers see pupils only as display name (minors: "First L."), never email or user id. Booking views for outsiders return 404.
21. A `ClockService` is injected everywhere time matters so tests control "now".
22. Notifications are an outbox table (`Notification`) with dedupe keys; email/push delivery arrives in S11.
23. Video provider: LiveKit behind a CallProvider interface (mock + real adapter). Reasons: open-source SFU that can be self-hosted later (data location), embedded TURN, simulcast/dynacast for weak networks, per-room JWT tokens, webhooks for authoritative presence; cloud pricing 5,000 free min then ~$0.0005/min (see docs/CALLS.md). Jitsi/Daily/Agora/100ms compared there. No own media server.
24. Call tokens go only to the teacher and the booked pupil (not the booking guardian), only inside the join window, 10 min TTL, anonymous per-room identities; the room name is never sent to clients. Reason: least privilege; guardian observation is a product/safeguarding question for the lawyer list.
25. Presence is authoritative from provider webhooks when a real provider is used; the mock provider accepts client heartbeats. Reason: clients must not be able to claim attendance (and earnings).
26. Lesson outcome is computed from presence: billable = time both were present (capped at the scheduled length); under 5 min together = FAILED for review, not COMPLETED. Reason: accurate duration for earnings; ambiguous cases go to a human.
27. Dependencies: only `puppeteer-core` (dev, no browser download) added for the headless smoke test; it drives the already-installed Edge/Chrome. LiveKit native packages NOT added to mobile (large, native rebuild); documented in docs/CALLS.md.
28. The call state machine is pure TypeScript in shared/ with a byte-identical copy in mobile/src/call (test enforces equality), because Metro does not resolve files outside the app folder here.
29. i18n: lightweight own `t()` with uz/ru/en dictionaries in mobile/src/i18n (no new dependency); key parity test lands in S11.
30. A headless two-browser smoke test found a real race (both participants requesting tokens at the same moment created two rooms, so they could never meet). Fixed with a partial unique index (one ACTIVE room per booking) plus conflict handling; regression test added. The smoke test itself failed once in ~9 attempts for an unexplained reason (see TEST_REPORT).
31. Messaging: one ChatThread per (teacher, pupil) pair, opened only from a real booking (not cancelled/declined); strangers get 404. Guardians of a minor pupil get READ-ONLY access (list/read + live copy) while their link is ACTIVE. NEEDS LAWYER (minors' privacy vs. safeguarding oversight).
32. Delivery state is derived from per-side `DeliveredSeq`/`LastReadSeq` (monotonic, clamped to lastSeq), not per-message rows. Reason: cheap, race-free for 1:1 threads. Messages are plain text, max 2000 chars; clients must render as text.
33. Real time: socket.io gateway is server->client only (message, receipt); sending goes through REST so validation/rate limits live in one place. Sockets can only join their own `user:<id>` room after JWT + ACTIVE check.
34. Files: own pipeline with an `ObjectStorage` interface and a LocalDiskStorage adapter; signed URLs (HMAC bound to op, file, part, user, expiry) emulate S3 presigned URLs. Chunks of 1 MiB, resumable via /files/:id/resume. No S3/R2 adapter was written (no account/keys): KNOWN_GAPS.
35. Allowed types: JPEG, PNG, WebP, PDF only, detected from bytes (declared mime must match). Images are decoded and RE-ENCODED with sharp (strips EXIF/GPS/XMP, applies orientation, kills polyglots, proves the image is valid) and get a 320px WebP thumbnail. PDFs: header at offset 0, %%EOF, and any /JavaScript, /JS, /Launch, /EmbeddedFile, /OpenAction, /AA, /RichMedia, /XFA reject the file (conservative). Dependency added: `sharp` (~20 MB prebuilt binaries); `socket.io-client` dev-only for tests.
36. Malware scan: ScanProvider hook (ClamAV clamd adapter written, UNTESTED). Without a scanner files end as scanStatus NOT_SCANNED; FILE_SCAN_REQUIRED=true makes uploads fail closed (quarantine). 
37. User files are only ever served via signed URL with Content-Disposition: attachment, nosniff, CSP sandbox, no-store; recommend a separate origin (FILES_PUBLIC_BASE_URL). Credential files: owner or admin reviewer only, admin downloads are audited; admins cannot use that route for message attachments.
38. Migrations after the partial-index one are written from `prisma migrate diff` output (Prisma `migrate dev` refuses non-interactive runs once hand-written SQL indexes exist); the diff was checked to contain no DROP statements.
39. Discovery lists only VERIFIED teachers with ACTIVE accounts; the `verified` filter is therefore always on (listing unverified teachers to pupils/minors was rejected, see 11). Ranking is documented in every response (`ranking.description`, `paid:false`): rating = Bayesian average (prior 4.2, weight 5, env-tunable), tie-break review count then id. There is no sponsored/boost field anywhere, and a test proves price/instant-booking do not change rating order.
40. Search uses ILIKE over headline, bio and name with pg_trgm GIN indexes on headline/name, GIN on subjects/levels/languages, partial btree indexes for rating/price/newest on VERIFIED rows (migration 20261011060000, hand-written; `migrate diff` will list them as DROP, never apply that part). Availability filter computes real free slots for up to 300 candidates (bounded) rather than approximating.
41. Reviews: only COMPLETED lessons, one per booking (DB unique), written by the booking creator (the pupil themself if adult, the guardian for minors; minors cannot review), within 30 days; author can edit within 48h; teacher replies once (editable 48h). Public author name is "First L.". Aggregates are recomputed from VISIBLE reviews only (idempotent) and ranking uses the Bayesian average (prior 4.2, weight 5). New teachers start at the prior mean.
42. A generic `Report` table + `ReportsService` was introduced here (REVIEW target now; USER and MESSAGE targets in S9) with an admin queue (`/admin/market/reports`), resolve = ACTION (hides) or DISMISS, everything audited.
43. Time-dependent columns (`createdAt` of reviews) are set from the injected clock, not DB defaults, so tests with a fixed clock behave like production.
44. Money: integer tiyin everywhere (BigInt in ledger/payouts, safe-integer checks); commission rounds half up and is snapshotted per payment (bps); refunds round down; teacher net = earned - commission so no tiyin is lost (property-tested).
45. Ledger: append-only double-entry (DB trigger forbids UPDATE/DELETE, every txn sums to 0, idempotent keys, per-teacher advisory lock for balance-changing flows, internal accounts may not go negative). Accounts: EXTERNAL_PAYMENTS, ESCROW, TEACHER_PENDING, TEACHER_AVAILABLE, PAYOUT_PENDING, PLATFORM_REVENUE, EXTERNAL_PAYOUTS.
46. Settlement policy (defaults, all NEEDS LAWYER/product decisions): full pay if >= 90 % of scheduled time was shared, else proportional; student no-show = teacher paid; teacher no-show/failed = refund (failed waits for admin); late student cancel = 0 % refund; 24 h hold before the teacher can withdraw; disputes only during the hold.
47. Payments are driven by domain events from booking/calls (completed, no-show, failed, cancelled, declined, expired) so booking code does not know about money. State changes use compare-and-set (updateMany with expected state) so repeated events never pay twice.
48. Payment is optional for joining calls by default (`PAYMENT_REQUIRED_FOR_CALLS=false`) because no real processor exists; the gate is implemented and tested (402).
49. Only a MockPaymentProvider exists; `PAYMENT_PROVIDER` other than mock is refused; in production the mock disables payment routes (503) instead of pretending to charge.
50. Minor safety defaults (all NEEDS LAWYER): pupils 13-17 are "restricted" until a guardian is linked: only a guardian can book/pay; messaging requires an ACTIVE guardian link; guardians get READ-ONLY access to the pupil's threads; chats with minors (and with pupils whose birth date is unknown) reject phone numbers, emails, URLs, handles and messenger names (code CONTACT_INFO_NOT_ALLOWED). Guardian linking = pupil generates an 8-char one-time code (hashed, 24 h, replaces older codes), an adult GUARDIAN redeems it; we cannot verify real parenthood.
51. Blocks are user-to-user and symmetric in effect: messaging, booking, call tokens are refused and the teacher disappears from search; a guardian's block also applies to the child. Blocks are created from a thread or a teacher profile so users never need another user's id.
52. Reports: REVIEW, USER and MESSAGE targets share one table; thread reports store a snapshot (message + recent context) so moderators can still see it after deletion. ACTION = hide review / delete message / suspend account (teacher profile becomes SUSPENDED). Admins can also suspend/reinstate users directly. Everything is audited.
53. Terms acceptance (current draft version) is required before booking, messaging and submitting a teacher profile (REQUIRE_TERMS=false disables for dev). Legal texts are drafts, visibly marked, in uz/ru/en; the privacy text says plainly that messages/files are NOT end-to-end encrypted and that disk encryption depends on hosting (unconfirmed).
54. Rate limiting uses a per-user tracker (verified JWT) with IP fallback (ActorThrottlerGuard), so one abuser behind a shared mobile IP cannot throttle others and forged tokens cannot create fresh buckets. AuditLog.createdAt now comes from the injected clock.
55. Account deletion = anonymisation + purge: refuses while open bookings/unsettled money/teacher balances exist; wipes message content, files (bytes too), credentials, notifications, blocks, call events, exam-app learning data; keeps the user row (anonymised), bookings, payments/ledger, reports, audit log and consent proofs (periods NEEDS LAWYER). Reviews keep the star rating only. Guardian-initiated deletion/export for minors is not implemented.
56. A guardian must accept the (draft) guardian statement before redeeming a link code. The statement says plainly that School17 cannot verify guardianship.
57. Notifications: outbox + dispatcher. Channels: in-app inbox (rendered in the user's locale), Expo Push (free; `PUSH_PROVIDER=expo`, default `log` = nothing leaves the machine). No email channel (no paid/new service); email addresses are not used for notifications. Push text is generic and `data` carries only navigation ids (a test proved amounts leaked into push data and it was fixed): lock screens never show message content, names or money. Failures retry up to 5 times; DeviceNotRegistered removes the token.
58. i18n parity is enforced by `shared/i18n.spec.ts` (same keys, no empty values, same {placeholders}, really translated, every literal t('key') in the app exists, no unproven security claims). Notification templates are tested the same way against every `notifications.enqueue(type)` found in the source.
59. Mobile marketplace UI added as a "Lessons" tab menu + screens under app/market (search, teacher+booking, lessons, threads/chat via 5 s polling, notifications, safety/privacy incl. guardian code, blocks, terms, export, delete). Shared StateView gives loading / empty / error / offline states (statusCode 0 = offline). Type-checked only.
