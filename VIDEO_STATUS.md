# VIDEO_STATUS (R0, read-only audit)
- Backend media: CallProvider interface (backend/src/marketplace/calls/call-provider.ts). Adapters: MockCallProvider (tests/dev) and LiveKitCallProvider (livekit-provider.ts; mints HS256 tokens itself via jwt-hs256.ts, no LiveKit server SDK, no Room/participant admin API yet). Selected in call-provider.factory.ts. The LiveKit adapter was never run against a real server.
- Mobile client: app/call/[bookingId].tsx optionally require()s @livekit/react-native (NOT in package.json, so no video renders today). No react-native-webrtc, no LiveKit client in mobile deps.
- Dev build: yes. LiveKit/WebRTC native modules do not run in Expo Go; expo-dev-client is present and eas.json has a developmentClient profile. No dev build has been made.
- Rooms: one room per booking (calls.service.ts); sides are TEACHER and STUDENT only (b.teacher.userId / b.studentId), presence-derived outcomes and billing logic assume exactly 2 participants. Classes (up to 31) need a new session/room model; 1:1 stays as is.
- Smoke test (calls.smoke.spec.ts): headless Edge, two pages, real browser WebRTC peer-to-peer with fake camera/mic and MOCK signalling; proves our call state machine, token flow, drop + reconnect and accurate outcome. Does NOT prove: an SFU, TURN/restrictive networks, simulcast/dynacast, mobile SDK, real phones, CPU/bandwidth, more than 2 peers.
- Chat: bookings chat uses polling every 5 s in the mobile screen (POLL_MS); a socket.io gateway exists (messaging.gateway.ts, realtime.service.ts) but mobile does not use it.
- Files: ObjectStorage interface (files/storage.ts: put/get/exists/size/list/delete/deletePrefix) with LocalDiskStorage; chunked 1 MiB resumable upload; sharp for images; no PDF renderer yet (pageCount only from sniffing).
- PDF-to-image tools on this machine: none of pdftoppm, mutool, gs, magick, qpdf. Node: sharp 0.35 only (it cannot rasterize PDF without a poppler build). ffmpeg exists (not a PDF renderer). Windows convert.exe is the disk tool, not ImageMagick. A PDF renderer package (e.g. pdfjs-dist + @napi-rs/canvas or mupdf wasm) would need to be installed: R5 decision.
- Media servers here: livekit-server no, lk no, ./tools missing. Docker CLI exists; the daemon status is probed separately before use. Official release binaries may be downloaded into ./tools/ (gitignored) with checksum.
- Unverified overall: anything on real phones, any LiveKit server, TURN, Expo push.
