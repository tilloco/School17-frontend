# Running School17 on free hosting (for now)

Goal: get the backend reachable over real HTTPS, for free, so the app is usable beyond your
own machine. This is meant as a starting point you can upgrade later (see `docs/COSTS.md`
for the real paid setup with video calls, on your own domain `mamunapp.xyz`).

**What this gets you, free:** sign-in, profiles, booking, messaging, classes (text/files),
direct payment tracking, notifications -- everything except live video calls.

**What it does NOT include (on purpose, for now):**
- **Video calls.** Real video needs LiveKit, which needs real bandwidth -- there's no
  everyday-usable free tier for that. Calls are left switched to a safe "off" mode
  (`CALL_PROVIDER=mock`, `ALLOW_MOCK_CALLS_IN_PRODUCTION=1`) so the rest of the app works
  instead of the server crashing on startup. Turn video on later by setting
  `CALL_PROVIDER=livekit` plus `LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET`
  (LiveKit Cloud has a small free tier, or self-host per `deploy/README.md`).
- **Persistent file storage.** Render's free plan has no persistent disk. Avatars, payment
  screenshots, and class materials are written to local disk today (`backend/src/marketplace/files/storage.ts`)
  and **will be wiped** whenever the free instance restarts or redeploys. Fine for trying
  things out; not fine for real use. Ask to add a Cloudflare R2 (free 10 GB) storage adapter
  before relying on this for real.
- **Phone SMS codes.** Needs Eskiz.uz (paid, Uzbek SMS) or Telegram Gateway (~$0.01/code,
  already wired up, leave `TELEGRAM_GATEWAY_TOKEN` empty for now). Use Google sign-in in the
  meantime -- it's free and already wired up.
- **Always-on.** Render's free web service spins down after ~15 minutes idle and takes
  ~30-50s to wake up on the next request. Fine for testing; annoying for real users.

## 1. Free Postgres database -- Neon

1. Go to neon.tech, sign up (free, no card), create a project named `school17`.
2. Copy the connection string it gives you (starts `postgresql://...`). That's `DATABASE_URL`.
   Neon auto-suspends when idle and wakes itself on the next query, no action needed.

## 2. Free backend hosting -- Render

1. Push this repo to GitHub (Render deploys from a GitHub repo).
2. Go to render.com, sign up (free, no card), click **New -> Blueprint**, pick this repo.
   It reads `render.yaml` at the repo root and creates a free web service called
   `school17-backend` building `backend/Dockerfile`.
3. In the new service's **Environment** tab, fill in the values marked "set in dashboard":
   - `DATABASE_URL` -- from Neon, step 1. Add `?sslmode=require` at the end if it's not already there.
   - `ALLOWED_ORIGINS` -- your admin panel origin(s), comma-separated. If you're not running
     the admin panel yet, put a harmless placeholder like `https://admin.example.invalid`.
   - `APP_DATA_KEY` -- a real 32-byte key. Generate one and paste it in:
     - PowerShell: `-join ((48..57)+(97..102) | Get-Random -Count 64 | ForEach-Object {[char]$_})` (quick hack), or better:
       `[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))` -- just needs to decode to exactly 32 bytes.
     - Or on the Render shell once it's up: `openssl rand -hex 32`.
   - `GOOGLE_CLIENT_ID` -- same value as `EXPO_PUBLIC_GOOGLE_CLIENT_ID` in `mobile/.env`, if you want Google sign-in to work.
   - Leave `TELEGRAM_GATEWAY_TOKEN` and `SUPPORT_EMAIL` blank for now, or fill in if you have them.
   - `JWT_SECRET`, `ADMIN_JWT_SECRET`, `OTP_PEPPER` are auto-generated by the blueprint -- leave them.
4. Deploy. Watch the logs for `Backend ishga tushdi` (the Dockerfile runs
   `prisma migrate deploy` automatically on every start, so the database schema is created
   for you on first boot).
5. Create the first admin account from the Render shell (Shell tab on the service):
   ```
   node prisma/create-admin.js
   ```
6. Check it: open `https://school17-backend.onrender.com/privacy` in a browser (replace with
   your actual Render URL -- it's shown at the top of the service page). This is also the
   blueprint's health-check path.

## 3. Point the app at it

Edit `mobile/.env`:
```
EXPO_PUBLIC_API_URL=https://school17-backend.onrender.com
```
(The old `mamun2appforuse.onrender.com` address in there is a dead placeholder from an
earlier attempt -- replace it.) Then rebuild the APK (see `docs/PLAY_STORE.md`) so the new
address is baked in, or run it with `expo start` for local testing.

`desktop/` defaults to the same placeholder (`desktop/README.md`); override it with the
`SCHOOL17_API_URL` environment variable when running the Windows teacher app, or update the default there too.

## When you're ready to go further
- Real video: LiveKit Cloud free tier, or the full paid VPS setup in `deploy/README.md` + `docs/COSTS.md`.
- Real file storage: ask for a Cloudflare R2 (or S3) adapter -- `KNOWN_GAPS.md` already flags this as unbuilt.
- Always-on + your own domain (`mamunapp.xyz`): move to the paid VPS setup (`deploy/README.md`); it's one Docker Compose stack with Caddy doing HTTPS automatically.
